People, API keys and project members now live in the session store, next to the settings (TR-1608). A start copies the rows from the DuckDB file into tares.sqlite and checks the counts, and on Postgres the existing tables are taken over as they are. Nothing changes in the console or the API.
 A person, a key or a project member added from now on is in tares.sqlite, so keep that file with the DuckDB file when you back up or move a cell.
 Going back to the release before this one (the migration's downgrade does nothing) leaves the old DuckDB copies of these rows, which are as they were at the first start: a key revoked since then works again until you revoke it again.
