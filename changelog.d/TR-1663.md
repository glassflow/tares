Fixed
When the merge queue had written its own pass after a branch update, ticket, project, review and merge queue pages could show a pull request as passed after the reviewer had asked for changes or blocked it (TR-1663). They now show the reviewer's verdict, except the review summary line on a project's Tickets view, which still shows the newest round. A pull request approved only by the `factory/review` status is no longer merged after a branch update while the status on the new commit does not pass: it enters the queue again once the status passes.
