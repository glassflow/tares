Fixed
A pull request marked ready while its draft run was still going stayed "CI failing" in the merge queue, and Tares asked for changes it did not need, until a new commit was pushed. Marking it ready starts a new CI run that cancels the draft run, and the draft run's cancelled jobs (some still under their unexpanded matrix names, which no later job shares) were counted as failures. Now a job cancelled in a run that a later run of the same workflow on the same commit replaced is no longer counted; a cancel with no later run still fails the checks.
