Fixed
On a cell without a state database, ingest could stall while a page was loading: a read of the session store held SQLite's write lock until it finished, so every `/ingest` that came meanwhile waited for it, and a long one could make it fail. Reads of the session store no longer take that lock. A read made of several queries still answers from one state. Cells on Postgres behave as before (TR-1702).
