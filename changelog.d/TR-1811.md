Changed
The source catalog, its connectors, the OTLP receiver and the platform reads are removed (TR-1811). A cell no longer polls a source, takes OTLP logs, traces or metrics, or answers /read, /catalog, POST /remember, the source routes (/api/sources, /api/connectors, /api/discover, /api/labels/preview, /api/resources, /api/catalog export, import and dependents), a project's sources, outline, health, stats, repair and actions, or the guided project setup (/api/setup and a project's setup). `/ingest/<key>` takes a GitHub App's webhook on the key it was made with and answers 404 for any other key; Claude Code and Codex lines still come in on /ingest/claude_code and /ingest/codex. An App credential's webhook key is made with the credential, its events go under `github` (`github_<credential>` for a second App), and the settings row still shows the key and the deliveries. On upgrade, the webhook key of each GitHub App source is kept for its credential before the source table is dropped, so an App's hook URL keeps working. The MCP tools read, stats, catalog_list, catalog_describe, list_connectors, discover_source, discover_docker, test_source, create_source, list_sources and source_fields are gone, with the setting that turned them on (/api/settings/mcp). `tares status` is gone, and so are the shared code context and Rius RCA templates: a project made from one opens as a custom project, and a project holds no sources, triggers, agents or MCP servers. /api/usage no longer counts events per source. asyncpg, pyyaml and the otlp-grpc extra (grpcio, opentelemetry-proto) are no longer dependencies, and TARES_CATALOG, TARES_CATALOG_SYNC, TARES_OTLP_GRPC_PORT, TARES_MCP_URL and TARES_MCP_OBJECT_TOOLS are no longer read. Plugin 0.6.15 drops the source catalog from the tares skill.
