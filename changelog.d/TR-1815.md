Changed
Tares no longer needs DuckDB (TR-1815). Every line and every table is in the session store: `tares.sqlite` in the
data directory, or the Postgres database `TARES_STATE_DSN` names. A new data directory holds no `.duckdb` file, and
`duckdb` and `pytz` are no longer installed with Tares. `TARES_DB` is no longer read: the daemon keeps its data in
`TARES_HOME` (`tares up --data-dir` sets it), and a daemon started with only `TARES_DB` says where its old store is. `/health`, `/api/usage` and the storage metrics measure the session
store (on Postgres, the cell's own schema) plus the archive against `TARES_MAX_DB_SIZE`, so transcript lines that fill the limit pause ingest again. A
start no longer reads the stored lines: it is ready in about a second on a factory-sized cell. A session line the
store refuses is counted and the session marked incomplete, but the line is not kept, since there is no second copy.
An existing cell's DuckDB data is moved by a one-time migration (TR-1821).
