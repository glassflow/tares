Fixed
A crew station could still write to Slack through a third-party Slack MCP server (a tool such as `conversations_add_message`) or through a write tool whose name the T20 deny rules did not list. The guard hook (`tares hook guard`) now refuses every tool of an MCP server with slack in its name (the Slack plugin included, any case) that is not on its read list (`SLACK_READ_TOOLS` in `claude-plugin/hooks/guard.py`: the Slack plugin's read, search, list and get tools and the common third-party reads such as `conversations_history`). A hook decides in every permission mode; Claude Code has no per-tool allow list for a server, and in auto mode a tool no rule names is left to a classifier. A read tool missing from the list is refused until it is added there. The server is found by its name, so a Slack server called something without slack in it is not held to this.
