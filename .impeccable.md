# Tares console: design context

Read by the `impeccable` family of design skills (`/critique`, `/polish`, `/distill`, ...) and by the
`glassflow-paper-design` skill before any design work on the console (`ui/`). It sits at the repo root
because that is where those skills look. The rules an agent follows while coding are in the
"Console design" section of `AGENTS.md`; this file is the why behind them. Update it when the direction
moves, in the same PR as the code, not per PR.

> **Skills.** `glassflow-paper-design` (repo `glassflow/arche-design`, `skills/`) is the shared GlassFlow
> paper direction, used by Rius (`argus-ui`) and Tares. Rius is its source of truth; where Tares differs,
> the difference is chosen and dated below. `glassflow-etl-ui-design` is the old dark-glass system of the
> ClickHouse ETL UI; never take colour, shadow or card guidance from it here.

Each convention below is one sentence or a few, dated. "(target, TR-NNNN)" means the rule is decided but
the code does not follow it yet; that ticket brings it in. A lint gate is named once it exists.

## Design Context

### Users

Engineers who give a crew of agents real work and come back to it between other work. Tares has two
editions, and each Tares a person creates is one of them.

- **Software Factory owner, at a desk.** Plans a project with Claude Code, then checks in: what the crew
  shipped, what waits on a decision only they can make, which PR is stuck in review. Reads the Home and
  Projects pages, answers decisions, and leaves. Wants the one thing that needs them on top, and the rest
  quiet.
- **AI SRE on call.** Agents watch their services and say what broke and why. Arrives from a notification,
  often on a phone, and needs the incident, its timeline and the cause the agent found, with nothing cut
  off below 640px.
- **Keyboard or screen reader user.** State is a word, not a colour; focus is visible on every control.
- **Lead reporting upward.** Counts sessions, merged PRs and incidents for someone else, so every number
  carries its caveat (sample data, a partial window, a capped list).

Jobs, in order: see what needs me now (Home) → answer it → follow a project or incident to its end →
set up connections and rules.

### Brand Personality

Product is **Tares** (company: GlassFlow), sister to Rius and built from the same kit. Three words:
**instrument, not costume.** Warm, mechanical, opinionated: a printed standards manual with live work on
it (NASA and EPA graphics standards, the Swiss grid, Tufte). Nothing shouts, so the one thing that does
(a failure, a decision waiting on you) is unmissable. Emotional goal: calm trust in a crew you are not
watching.

### Aesthetic Direction

- **Paper, not panels.** Cream ground, brown ink, content directly on the paper. Regions are separated by
  1px rules and whitespace, never by cards, shadows, glass or gradients. A panel is a 1px `border-border`.
  Floating layers (sheets, menus, popovers) cast `var(--sheet-shadow)`, and the selected item carries an
  inset accent bar; nothing else in the page has a shadow, and no region carries a side stripe (a left
  border wider than 1px). (Chosen 2026-11-12, TR-1251. Gate: `npm run design-contract`, shadow and
  stripe selectors, with no shadow exceptions since TR-1266.)
- **Kit first.** Screens are built from `@/components/edition` (`ui/src/components/edition`). Look at
  `/dev/components` (`ui/src/pages/dev/Components.tsx`) before writing a component; a new one joins the
  kit with a gallery section. Copy from `ui/src/editions`, never from `ui/src/pages`, which predates the
  kit (TR-1250, TR-1267).
- **Type carries hierarchy.** Inter for text. Geist Mono for operational labels, table heads, state
  words, ids and code, and nothing else: buttons, body text and headings are Inter. Doto (dot-matrix) for
  headline numerals, the same face as Rius. Square geometry; `rounded-full` only for dots and switches
  (gate: `npm run design-contract`). The kit's headline numeral is `Stat`; Doto is `--font-pixel`
  (`font-pixel`). Every edition e2e state checks that no button, heading or sentence computes to mono or
  Doto (`ui/tests/type.cjs`). (Chosen 2026-11-12, TR-1251: align with Rius. Built in TR-1270.)
- **Pictures of the kit.** Every gallery section has a committed picture in light, dark and at 390px
  (`ui/tests/visual/__screenshots__`), and CI's `visual` job fails when a token or a padding moves a
  pixel. The pictures are drawn only in the Playwright Linux image (a Mac's font hinting never
  matches), so from a Mac run `npm run test:visual` (needs Docker). A change that moves the kit on
  purpose runs `npm run test:visual:update`, looks at every changed picture, and commits them with the
  change. The `a11y` e2e suite runs axe (WCAG 2.1 A and AA) on the gallery and on two edition pages:
  a serious or critical finding fails, unless it is listed in `KNOWN` in `ui/tests/a11y.e2e.cjs` with
  its reason, and that list may only shrink. (TR-1269.)
- **Figures, not widgets.** A chart is a numbered figure in reading order with a mono caption; a page
  opens with a running head and one sentence computed from the data. Charts default to ink.
- **States are typographic.** A mono word with a 1px coloured underline, from `StatusLabel`: ready jade,
  done plain, failed rose, live work amber, waiting a dashed neutral underline in `--ink-soft`,
  stale, not started and out of play a dashed `--ink-faint`. A page never picks a tone: it looks
  its status up in `STATUS_TONES` (`components/edition/statusTones.ts`), whose tables tsc checks
  against the API types, and `/dev/components` shows every one. (Chosen 2026-11-12, TR-1251; built
  TR-1265.)
- **Empty and loading are typeset too.** One kit component each. Nothing there: `EmptyState`. With a
  `title` it is a block for a page or a list with nothing in it (a title, one sentence, maybe an
  action); without one it is a line where an empty section's rows would be ("No pull requests yet.
  Each one the crew opens for a ticket shows here."). Loading: `Loading` around `Skeleton` bars laid
  out as the loaded page will be, so nothing jumps when the data comes: `LoadingBlocks` for a list
  page, `SkeletonRows` for a list section, `SkeletonLines` for a block of text. No spinner, and no
  "Loading…" line where the page has a layout to stand in for. (TR-1264.)
- **Colour budget.** Amber (Space Sand) means one of three things: the primary action, the selected
  item's edge, live work. Rose means failure. Colour appears only when something is wrong, selected or
  moving. Colour comes from the semantic utilities, one name per role, never hex, `rgb()` or
  Tailwind palette colours, and never `text-[color:var(--err)]` for a role that has a name (gate:
  `npm run token-contract`, TR-1256, TR-1263). The raw values (`--kit-*` in `ui/src/paper/paper-theme.css`, with the roles and `@theme inline`;
  motion is in `ui/src/paper/paper-motion.css`) are the shared paper tokens of arche-design, vendored with their tag and commit by `npm run paper:sync`
  into `ui/paper/tokens.css` (`ui/paper/VENDORED.json`; `npm run test:paper` stops hand edits);
  `npm run test:tokens` fails in CI when one drifts. To change a shared value, change it in arche-design,
  tag it, then run `npm run paper:sync`. To differ on purpose,
  list the token in `ui/tests/tokens.parity.allow.json` with its reason and ticket. (TR-1268.) The roles, as `bg-`, `text-`, `border-`, `stroke-`
  and so on:
  - Surfaces: `background` (canvas), `card` (panel), `popover` (floating lists), `field` and
    `field-focus` (inputs), `row-hover`, `wash` and `wash-strong` (a tint over any surface),
    `scrim` (behind a dialog or drawer), `muted` (hover).
  - Ink: `foreground`, `muted-foreground` (secondary text), `faint` (the quietest: separators,
    idle marks).
  - Rules: `border`, `rule-strong`.
  - Action: `primary` and `primary-foreground` (the button), `brand` (amber as a colour: the
    selected edge, live work), `brand-soft`, `brand-deep` (amber text), `brand-foreground`,
    `ring` (focus only).
  - State: `ok`, `warn`, `err`, each with `-soft` (a tinted background) and `-border`; `track` (the
    unfilled part of a meter).
  The code palette on the dark code surface (`--code-dark-*`, `--on-brown-*`, `--green-300`,
  `--red-300`) has no utility on purpose: it lives in `editions/factory/codeColours.tsx` and nowhere
  else.
- **Time.** Two grammars. An instant is a UTC stamp in mono, `2026-11-12 14:05Z`, with "3h ago" in its
  tooltip. A calendar day is `Nov 12, 2026`. Never a locale string, never a relative phrase in a cell.
  One module says both, `ui/src/lib/time.ts` (TR-1261); `npm run design-contract` fails on a
  `toLocale*String` call or `Intl.DateTimeFormat` anywhere else.
- **Words.** Edition screens use the words in `ui/src/editions/WORDS.md`, gated by `npm run test:words`.
  No em dash in any string a reader sees: an aside becomes its own sentence, an explanation takes a
  colon, a list takes commas. A lone dash glyph as the no-value mark in a cell is the one exception.
  (Chosen 2026-11-12, AGENTS.md. Gate: `npm run design-contract` reads every string in `ui/src`; the
  words check reaches `src/pages` with TR-1259.)
- **Theme.** Light is the primary theme. Dark follows the kit V2 ladder, the same as Rius: canvas
  `#2b1600`, panel `#492400`, a field-focus rung `#582f06` and a segment rung `#783e06` for overlays, so
  chrome and content never share one brown and rules stay visible. Menus, selects and other floating lists
  take `--popover` (the segment rung in dark); a focused field takes `--input-bg-focus`. (Chosen
  2026-11-12, TR-1251. Built in TR-1271.)
- **Motion.** Things arrive and leave; nothing jumps. A change the reader did not cause moves into
  place: an overlay fades and rises, a banner or a fold grows open, a row that moved glides, a value a
  poll changed washes once. The page itself never performs. Nothing animates on first paint, nothing
  loops but a running state, and nothing moves for decoration. Four durations and two curves, all
  tokens (`--dur-1` 120ms for hover, press and menus, `--dur-2` 180ms for dialogs, folds and banners,
  `--dur-3` 260ms for page content, the phone menu and rows, `--dur-4` 900ms for a wash fading);
  arrive on `--ease-out`, leave on `--ease-in`, faster than you came. A skeleton waits 200ms before it
  shows. Under `prefers-reduced-motion` all of it is instant. (Chosen 2026-11-17, replacing "work
  surfaces snap": Tares can afford the weight Rius cannot, and a snap that shoves content reads as a
  jump. Built in TR-1431 to TR-1436. Gates: `npm run motion-contract` for CSS and the e2e suites, the
  motion selector of `npm run design-contract` for components.)
- **Anti-references.** Grafana-style dark cockpits with glowing accents; icon-topped card grids;
  side-stripe callouts; gradient text; sparklines as decoration; modals where a page would do.

### Design Principles

1. **Edit before you design.** The biggest wins are cuts: fewer panels, fewer columns, one grammar per
   concept. Add a component only when nothing in the kit fits.
2. **One convention per concept.** Time, table heads, state words, empty and loading states: one home
   each, written down here and in `AGENTS.md`.
3. **Colour means trouble, selection or motion.** If amber or rose is on screen, the reader can say why
   in one clause.
4. **The decision that is yours comes first.** The crew works without you; the console exists for the
   moments it cannot. Put those on top and keep the rest quiet.
5. **Numbers come with their caveat.** Sample data, partial windows, capped lists: say so beside the
   number, in the same mono voice, not in a banner.
