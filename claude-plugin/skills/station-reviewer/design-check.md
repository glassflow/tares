# Design check, for a screen ticket

Part of the station-reviewer manual. Read when the ticket's working doc starts with `Screen: yes` (step 6 of Per review).

A screen that works but does not look like its approved mock fails review.
- Find the approved mock: the PR body names it (`Mock: "Mock: <screen>" (desk D<n>)`). Read the doc with `list_docs` and `get_doc`, and check the decision with `list_decisions(project)`: the one labelled D<n> has a `choice` (or, when `choice` is null, `words`) that starts with "yes" or "approved" (any case), and neither its `choice` nor its `words` asks for a change; and its `at` is before the first UI commit, compared as timestamps, not as text: the earliest author date: run `git fetch origin <base>` on its own and check its exit code (it writes progress to stderr even when it works), then `set -o pipefail` and `git log --format=%at origin/<base>..<head> -- ui/ | sort -n | head -1`, with `<base>` the PR's base branch (from `gh pr view <url> --json baseRefName`) and `<head>` the SHA pinned in step 2. Use `origin/<base>`: your checkout may have no local `<base>` branch, and a stale local one widens the range. `at` is ISO and `%at` is epoch seconds: convert `at` to epoch before comparing. `--reverse` is topological order and does not always give the earliest author date; committer dates move on a rebase. A git error (the fetch exits non-zero, or the log exits non-zero or prints a `fatal:` or `error:` line) is not "no output", and without `pipefail` the exit code of the pipe is `head`'s, which hides a bad ref: fix the command and run it again. Only a clean run with no output means no UI commit, which for a screen ticket is a `block`. No approved mock, or UI commits older than the approval: `block`. A mock file or real names committed in the PR: `block`.
- Run the PR's e2e script from the worktree with `SHOTS_DIR` set (`cd ui && npm run build && SHOTS_DIR=<dir> node tests/<name>.e2e.cjs`). It must screenshot every state the working doc lists (at least empty, loading, error, long text, many items) at desktop width and at 390px. A missing state is a blocking finding.
- Open each screenshot next to the mock (Read the PNGs and the mock HTML). Compare layout, order of sections, wording, what comes first, colours and spacing. Each visible difference is a finding with the state and the screenshot name; a difference the approval did not allow blocks. Data differences (invented names in the seed, real names in the mock) are expected.
- The script calls `checkWords` and `expectOneCall` from `ui/tests/words.cjs` in every state, and `cd ui && npm run test:words` passes. No internal name, no em dash, one read call per screen.
- Name the screenshots you compared in the verdict.
